# 主动回访与次日早安

## 一小时回访

- 用户一轮对话回答完成后，只调度一次 3600 秒后的主动回访。用户继续发消息时，旧活动版本的回访失效，按最新回复完成时间重新计时。
- 默认配置与示例只保留 `[3600]`。兼容旧配置时仅采用第一个间隔；Redis 中旧的第 2、3 阶段任务直接忽略，不会补发。
- 既有长期记忆提取和延迟话题推荐保留不变。

## 次日早安

- 按应用时区（默认北京时间）计算「昨天」。昨天确实有用户发送的聊天消息，才会在今天安排早安；单纯打开页面、助手主动发言或只有更早的聊天不触发。
- 昨天聊过的每个伙伴分别安排早安，每位伙伴每天最多一条，独立随机发送时间，使用其当前身份、昵称、性格和专属设定。同一伙伴有多段会话时选昨天最后聊天的会话；切换伙伴不改变既有聊天归属。
- 从 07:00（含）到 09:00（不含）随机选择一个秒级时间点。首次启动已在窗口内时，在剩余窗口随机安排。实际发送受 30 秒轮询与生成耗时影响，不承诺秒级到达；生成完成已过 09:00 则不发送。
- 随机时间和状态保存在 `morning_greetings` SQL 表中；重启不重新抽时间。唯一用户/伙伴/日期约束、任务租约及事务阻止并发重复发送。失败在窗口内最多尝试三次，错过窗口不在下午补发。
- 只参考昨天与该伙伴的聊天，不混入其他伙伴的聊天；长期记忆包括用户全局、当前角色和当前关系记忆。称呼与表达风格来自资料和该伙伴的性格偏好，不写死统一话术。
- 早安不依赖一小时回访的活动版本，因此今天新聊天不会错误取消昨天产生的早安资格；独立 worker 不阻塞一小时回访。
- 删除/禁用伙伴后跳过其早安。消息与当日发送标记在同一事务提交；启用推送时推送 outbox 也一起提交，继续使用已有消息、未读数和通知流程，无需修改安卓协议。

## 天气真实性

- 只有 Redis 中有未过期地区，才尝试查当日地区级天气；坐标使用公开地区地理编码结果，不是用户精确坐标，不持久化。
- 天气采用 [Open-Meteo 地理编码 API](https://open-meteo.com/en/docs/geocoding-api) 和 [天气预报 API](https://open-meteo.com/en/docs)。地理编码限定中国及省级范围，区县无结果时尝试城市；拒绝日期不符、缺失或未知天气代码的数据。
- API 超时/失败、定位缺失/过期、结果不可靠时，早安仍可发送，但提示模型完全省略天气和温度，不从历史记忆猜测天气。不把地区级预报说成用户所在街道的实况。
- Open-Meteo 及其地理编码数据源 GeoNames 应保留来源署名；公共接口的免费使用面向非商业场景，商业部署应按提供商条款配置服务，不能把免费公共接口当作商业 SLA。

## 发布

启动数据库初始化时自动创建新表，并升级之前按用户/日期去重的 SQLite 早安表，保留已安排及已发送记录；上线应先备份数据库/配置再重启服务。存量定时任务通过阶段校验兼容，无需清空 Redis。

安卓「我的」页面移除「使用当前地区」开关与对应说明，仅移除展示入口，不取消已有的启动定位、权限校验和地区同步功能。此界面变化需要更新安卓包才会在手机上生效。
