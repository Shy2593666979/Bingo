# 后台任务

每次助手完成一轮回复后，服务端会安排：

- 立即抽取长期记忆和用户资料；
- 用户闲置 1 小时后发送一次结合上下文的主动回访消息；
- 用户闲置 5 小时后生成 3 条结合上下文的对话推荐。

用户发送新消息后，活动版本会变化、推荐会被清除，旧的主动回访和推荐任务会失效。记忆抽取仍然有效，因为每次完成的对话都可能包含需要长期保存的资料信息。

Redis 使用以下固定键名：

```text
bingo:jobs:scheduled
bingo:job:{job_id}
bingo:user:{user_id}:activity_version
bingo:user:{user_id}:last_active_at
bingo:user:{user_id}:recommendations
```

Android 客户端会在登录时、回到前台时以及应用活跃期间每分钟一次获取待处理消息和推荐。它会先将主动消息保存到对应伙伴的本地对话，再确认已收到。应用关闭后的通知送达需要配置推送服务，见[推送通知](push.md)；未配置时依赖前台同步。

昨天聊过的每位伙伴还会独立安排次日 07:00～09:00 的随机早安。早安调度持久化到 SQL，参考该伙伴昨天的聊天和长期记忆；它不依赖一小时回访的活动版本。去重、重试、天气真实性与部署说明见[主动回访与次日早安](proactive-greetings.md)。
