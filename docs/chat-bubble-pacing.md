# 聊天气泡展示节奏

客户端正常接收并保存完整回复，仅延迟新回复气泡的展示，不改变模型生成速度、气泡切分或服务端历史。

- 第一条气泡立即显示。
- 后续间隔按即将出现的当前气泡的 Unicode 字符数计算：`(0.6 + 字数 × 0.04) × (0.85～1.15)` 秒，最后限制在 1～3 秒。
- 每次间隔仅抽取一次随机值；从上一条实际展示时刻开始计时，扣除网络等待时间。
- 队列未展示完时仍显示正在输入，闹钟等操作卡片跟随最后一条文字展示。
- 历史消息恢复不排队；发送新消息、离开聊天或解除账号绑定时取消旧展示计时，已收到的消息仍保留。
- 朗读事件携带 `segment_index`，每个气泡音频完成生成时发送 `audio_segment_done`。后台继续生成后续气泡的声音，客户端先缓存，仅在对应气泡展示后播放。
- 普通聊天在完整气泡切分后立即开始合成该气泡的声音，不等待整个模型回复结束；不再在气泡尚未定稿时直接播放零散文本的声音。睡前故事仍使用文本增量驱动合成。
- 下一条展示需要同时满足字数间隔和上一段实际播放结束。播放已经超过间隔时不额外再等；长语音会让实际间隔超过 3 秒。
- Android 的 `finishReplyAudio` 回调等待 PCM 实际播放完毕，而不是仅等音频入队。暂停朗读、离开页面或发送新消息会停止播放并释放等待。
- 旧后端没有气泡音频编号时，客户端仍按间隔展示文字，声音缓存至文字全部展示后播放，避免抢在文字前面。旧客户端可忽略新增字段继续播放。睡前故事保持原来的边生成边播放协议。

实现位于 `apps/mobile/lib/features/chat/presentation/bubble_pacer.dart`，测试覆盖字数、随机边界、队列顺序、中断、已有网络等待和流结束后的展示。
