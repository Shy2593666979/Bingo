# 闹钟确认与历史记录

闹钟请求在产生时保存为对话里的 `device_action` 消息，并与设备操作使用同一 ID。
确认、取消、成功、失败只更新这张卡片，不删除卡片，也不另造一条用户聊天文字。
历史接口附带设备操作信息，客户端恢复历史时还原为卡片；本地旧卡片在同步时也保留。
AI 上下文包含该记录的实际状态，状态改变后下一轮回复就能读取结果。

- 待确认：尚未执行，可以创建或取消。
- 待设备反馈：用户已批准，但执行结果尚未收到。
- 已创建：设备本地创建成功。
- 待系统确认：已启动 Android 系统时钟，没有成功回执，不能声称已经创建。
- 已取消：用户拒绝，不执行。
- 创建失败：展示设备错误，可以重新确认并重试。
- 待同步：设备已执行但结果上报失败，禁止再次执行；连接恢复后只重试上报结果。

已批准但应用进程意外退出的操作不会自动再次执行，以避免重复创建。
系统时钟没有提供可靠的创建成功回调，所以本版不会自动将“待系统确认”升级为“已创建”。
升级时为旧设备操作表增加可空的对话关联字段，不删除旧闹钟记录、用户数据或历史。
旧记录若没有对话关联，无法可靠推断所属伙伴；仅保留已有的本地卡片，不跨伙伴补写。
