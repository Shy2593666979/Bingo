# 群聊 v2 客户端与服务端实施

依据 确认过的完整 HTML（开发预览已清理） 实施，沿用现有 Flutter、SQLModel、SQLite、OpenAI 兼容模型接口与事件协议。没有替换单聊执行链，也没有引入 AG-UI。

## 客户端

- 群标题人数包含真人：最多 8 位 AI 加自己，共 9 人。成员页展示自己和搭子，使用圆角方形头像。
- 键入 `@` 才在输入框上方出现候选；第一项为「全部搭子」，支持多次选择。选中后保存角色 ID，删除、剪切或替换触及其中任意字符时整体移除。普通粘贴的同名文字不会获得成员身份。快捷键撤销/重做同时恢复文本和绑定身份。
- 点击发送立即显示本地消息和发送状态，不等待 HTTP 确认或历史请求。服务端事件/历史通过命令 ID 替换正式记录，不重复展示；每条未确认消息独立重试。
- 发送时保留选中的多个目标和全体标志，服务端去重。发送结果未确认时重试沿用相同命令 ID、引用和提及信息。
- 群消息保留头像、历史发送者名称及时间；引用回复显示预览卡片，点击定位并短暂高亮原消息。长按气泡提供引用和复制；失效原消息有明确提示。
- AI 可以提及真人；合法的真人提及显示「@我」，会话列表也显示未读提及标记。仅在运行时显示当前正在回复的搭子名称，移除进度条与 0/4 数字，可以停止本轮。
- 默认气泡按 HTML 调整圆角、字号、留白和颜色；已有图片气泡、自定义背景及带文字的表情继续使用。
- 群信息支持「暂停会话」，不删除历史。之后发送真人消息继续，原有主动话题和免打扰配置保留。

## 服务端执行

`social_agent_runtime.mode` 默认 `independent_agents`。每位候选搭子用自己的身份和记忆独立决定是否参与，普通消息由候选搭子自主参与；若全员选择沉默，则由一位接待搭子自然回应真人；主动话题仍可无人发言；`legacy_dispatcher` 保留作兼容回退。

真人明确 @ 的搭子属于强回应请求；`mentionAll` / `mention_all` 展开到全部有效 AI，绕过普通候选数量上限。被提及的搭子并发决策和生成，每位决策一结束就开始自己的生成，不等待其他人的决策。谁先返回第一段有效文字，谁先创建气泡并获得稳定消息序号；各气泡独立流式更新。全员首次回应结束后，再按 AI 接话开关决定是否继续。单个搭子调用失败会标记该条失败，其他搭子继续。

服务端限制每轮最多 **10 条可见 AI 消息**，失败和中断也占用名额。另有决策调用、生成调用、总时长、引用深度及角色对冷却限制。已暂停、已取消或版本过期的运行不能再提交消息。主动话题跳过已暂停群。

引用仅接受同群、已完成且存在的消息。真人提及只接受群主的真实用户 ID；AI 提及仅接受当前有效成员。角色的私聊记忆按既有约定允许在其群聊上下文使用，不读取其他角色的私人记忆。图片表情进入模型前转换为语义文字。

## 兼容与存储

- 历史表通过幂等增列迁移保留旧数据；旧运行标记为 `legacy_dispatcher`。
- SQLite 启用 WAL 和 5 秒 busy timeout；模型请求在数据库事务之外执行。
- 发送兼容原来的 snake_case 字段，并支持 `clientMessageId`、`mentionAll`、`mentionTargets`、`replyToMessageId`。
- 既有 `mentions: [roleId]` 继续可用。新增 `mention_targets: [{type: role|user, id}]`，引用附带历史名称和正文预览快照。
- 客户端继续每 450ms 补拉事件。事件保留顶层完整消息对象，`message_delta` 仍为全文快照；`/chat/stream` 仍为 NDJSON。终态事件分页通过 `has_more` 补拉到底，避免末尾遗漏。
- 新增 `GET /groups/{id}/messages/{messageId}/context`，检查归属后返回目标附近消息，支持旧引用定位。

## 并发与即时显示修正

新增确定性测试验证八路生成均已启动但未返回时，数据库仍仅有用户消息；按相反顺序释放模型文本，实际消息序号严格按文本到达顺序分配。停止时所有并发生成都会取消，不再补写。普通真人消息在所有候选沉默或决策格式异常时仍获得一条真实模型回复，不使用固定文案。客户端测试通过延迟 HTTP 确认，验证发送前即可看到本地气泡，并在确认后仅保留一条正式记录。

本轮检查：服务端全量 333 项、Flutter 全量 200 项通过，最新消息交互测试 6 项和静态检查通过。真实模型验证中，第一条回复结束前四位搭子的正文生成都已启动，四位全部完成；随后一条完全不带 @ 的「今天工作好累啊，想躺一会儿。」获得了两位搭子的正常回应，见 实机结果（开发预览已清理）。

## 首字延迟优化

实际用户消息「@全部搭子 你们都在干嘛」曾在约 19.3 秒后才创建第一条回复。定位到前置参与判断、模型深度思考以及每次请求创建连接等等待。

- 明确 @ 的目标直接启动生成，不再先调用一次决策模型。普通真人消息的首位接待搭子也直接生成；其余候选自主决定，且判断最多等待 3 秒。
- 可选引用和提及改成同一次流式输出里的短 JSON 首行，后接正文；服务器校验并移除该首行，客户端只接收正文。引用、AI @真人功能保留；普通闲聊优先空元数据，减少无意义的引用。
- 方舟 Responses 群聊单独使用 `thinking.type=disabled`、最多 1024 输出 token、可复用连接池；直连区域服务，避免系统代理绕行。单聊的既有模型配置不变；其他供应商不自动加入方舟专用参数。可通过 `social_agent_runtime.low_latency_chat` 和 `direct_ark_connection` 配置调整。
- 并发决策调用计数改为数据库原子累加，避免同时判断时漏计预算。

官方参数依据：[方舟 Responses 深度思考说明](https://docs.volcengine.com/docs/ark/responses-api-deep-thinking?lang=zh)。真实完整会话测试记录位于 `.tmp/group-first-token-result.json`：普通同句首字约 2.03 秒，首次 @全部约 5.94 秒（包含网络与事件补拉观测开销）。这是本次测量值，不是固定响应时限。

本轮服务端全量 338 项测试通过，Ruff 检查通过；后台已重启使用新配置，无需重新安装客户端。

## 真人指定的搭子转达

支持「让甜甜@暖暖给我说句话」「@甜甜 帮我叫一下暖暖」等明确转达。先按当前群内有效且名称唯一的角色解析并保存 ID；实际首位回应者是转达者，不会把正文里被选中的接收方误当成首位回应者。普通相邻的多个 @ 仍是并行点名，不当作转达。

转达者的消息保存真实 `role` 提及，后台按接收者 ID 发起下一次回复；接收者引用这条 AI 消息并读取它的上下文。真人明确要求的转达不受自主闲聊开关和角色对冷却拦截，同一命令的每条转达关系只执行一次；仍受消息数、链深、取消和归属权限限制。AI 自己发起的互相接话继续受 `allow_ai_to_ai` 控制，允许独立沉默；AI 提及真人不会制造假用户消息。

同时修正：被 AI 明确提及的候选不再被普通候选数量截断；处理所有已发布触发消息，链深单独限制；角色列表使用当前有效名字；可选元数据出错不再抹去已确认的真人转达对象。服务器命令记录中的 `_user_handoffs` 由后端计算，客户端不能提交此字段冒充授权。

验证：服务端全量 343 项通过。真实模型输出为甜甜「@暖暖 快来……」，随后暖暖接话，且 `reply_to_message_id` 指向甜甜的消息；记录位于 `.tmp/group-handoff-real-result.json`。当前预览群自主接话已恢复开启。
