# 推荐话题计时与缓存

- 每个用户的每个会话独立维护活动版本、定时任务和推荐缓存。
- 用户消息进入后台活动登记时，原子清除旧推荐并重置该会话的推荐任务：五小时后生成。
- 计时不等待助手完成回复；回复结束时不再重复安排推荐任务。
- 同会话继续发消息覆盖原来的定时任务，与其他伙伴聊天不会影响该会话。
- 推荐接口只读取缓存，没有缓存时返回空列表，不调用模型，不补生成。
- 后台生成结果写入 Redis 前原子核对活动版本。生成途中发消息或清除推荐，旧结果不会写回。
- 点击推荐或发送其他消息清除该会话缓存；实际发送的消息重新启动五小时计时。
- 新生成的推荐缓存不主动过期，保留到用户点击推荐、发消息或显式清除为止。
- 后台生成异常时最多重试三次，分别等待一分钟、两分钟、三分钟；旧版本任务不重试。

首次聊天的固定三个问题不受上述动态推荐机制影响。长期记忆提取保持原样。
