# 回复长度和聊天气泡

系统提示词按当前请求和上下文设置软目标，不额外调用分类模型、不按字数截断，也不把字数当成必须达到的下限。用户明确要求优先于默认长度。

| 场景 | 一次完整回复的默认中文长度 |
| --- | --- |
| 问候、早晚安、确认 | 通常 10～50 字，原则上 100 字以内 |
| 日常闲聊、轻度关心 | 40～120 字 |
| 倾诉、安慰 | 80～200 字 |
| 天气、推荐、普通问答 | 80～250 字 |
| 规划、讲解、复杂建议 | 300～700 字，必要时更长 |

普通聊天按完整句末分气泡，不按字数合并短句。模型在规划和讲解中使用“第一天上午：”“思路：”“步骤一：”等段落开头；代码识别这些结构化开头，保留段内完整说明，只在换行处拆分。不单独展示日期或步骤标题，将其与下一行具体说明合并。不在逗号、顿号或冒号切断，也不硬截没有句末的长文本。

连续句末标点、省略号和相邻的配对结束引号一起保留；引号、括号内部不切分，链接、小数、版本号和时间不按其内部符号切分。流式输出在末尾句末暂缓一个后续字符，以确认标点、引号是否完整；回复结束时立即刷新剩余文本。

后端流式分段和安卓历史分段采用相同规则，由 `apps/mobile/test/fixtures/assistant_segments.json` 的共享用例校验。WebSocket／流式事件协议保持不变。主动回访和早安问候仍有各自独立的长度要求。

验证以实际模型回复和手机阅读效果为准：软目标不保证每次严格满足，测试只在测试账号产生对话，不修改真实用户记录。
