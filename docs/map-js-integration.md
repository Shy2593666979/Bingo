# 安卓 JS 地图与预热

## 当前行为

- 安卓位置选择页使用 WebView 内嵌高德 JS API 2.0，保持现有搜索、附近地点、区县隐私选项和聊天位置卡片。
- 地图初始化与系统定位并行执行；地址解析仍走现有后端，WGS84 坐标转换继续由后端处理。
- 用户同意高德地图隐私提示后，将同意状态保存到手机本地。未同意时打开加号菜单不会访问地图服务；预热不调用设备定位。
- 打开加号菜单后预热 JS 资源。同一 Activity 内复用 WebView，退出位置页后最多保留两分钟。到期、Activity 销毁、取消同意时销毁缓存，初始化失败的实例不复用。
- 初次使用仍可能等待网络和隐私确认；预热不意味着提前下载任意当前位置的所有地图数据。更换区域、冷启动和弱网仍可能需要加载，不保证固定秒开。
- 地图失败保持静态地图回退，附近地点查询不会等待地图加载完成。

## 构建配置

通过环境变量或本机 Gradle 属性配置，不把实际凭据写到源码或 Git：

| 名称 | 用途 |
| --- | --- |
| `BINGO_AMAP_JS_KEY` | Web端 JS API Key |
| `BINGO_AMAP_JS_PROXY` | 官方 `serviceHost` HTTPS 安全代理地址，生产必须配置 |
| `BINGO_AMAP_JS_SECURITY_CODE` | 仅用于本次本机 debug 验证；release 中强制清空 |

生产代理应按照高德官方说明部署，安全密钥仅保留在代理服务端，限制转发路径与调用频率。此次没有修改服务器配置或部署代理，也没有生成手机 release 包。原生地图 SDK 依赖已移除，不再使用 Android SDK Key；JS 动态地图没有有效配置时保留静态回退。

官方参考：https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode

- LDPlayer 已安装本轮 debug 测试应用，连接本地后端，通过 `adb reverse tcp:8000 tcp:8000` 访问主机服务。用户原有数据未清除；验证使用专用本地测试账号，不向伙伴发送消息。
- 实际位置页截图能显示地图、搜索、附近地点和发送按钮；拖动选点后地址列表更新。
- 关闭应用、重新进入聊天，尚未点击位置、只打开加号菜单时，测试 WebView 已加载 JS SDK 并创建地图对象；当时 WebView 尚未进入可见布局。
- 关闭并重新打开位置页，WebView 的 `performance.timeOrigin` 完全相同，SDK 入口请求始终只有一次，证明实际复用而非重新创建。此结果不等同于精确的首屏耗时或正式手机流畅度测量。
- Flutter 全量测试 83 项通过，针对预热与位置的 10 项测试通过，静态分析无问题。

截图和调试结果保存在 Git 忽略的 `.tmp/map-lite-validation`。WebView 调试转发仅用于本机验证，完成后移除；后端与模拟器保持运行，便于继续体验。
