# 群聊附件与语音通话

群聊底部菜单仅显示照片、相机、电话、位置。群聊设置继续由顶部省略号进入。

## 通话流程

- 从当前群成员中选择 1–8 位 AI，真人用户自动加入，总人数最多 9 人。
- 独立 WebSocket `/groups/{group_id}/calls/stream?role_id=...`，使用登录凭证鉴权；后台校验群归属、成员有效性与重复选择。
- 麦克风 PCM 16 kHz 统一接入实时 ASR，断句后合并短间隔片段。文字提供给参与通话的角色，各角色使用自身人设与允许使用的记忆。
- 当前客户端默认自主群聊，调度器选择发言者，再由该搭子的独立 Agent 生成文字。
- 当前搭子文字生成后，播放其语音的同时调度下一位、生成下一位文字并预备首段音频；只提前准备一位，不预生成整场台词。
- 每位搭子使用自身音色，输出为 24 kHz PCM。下一位的字幕和音频仍在当前搭子的客户端播放完成确认后发送，没有固定的 1.5 秒等待。
- 用户新开口取消旧生成与待播内容，并立即清理客户端音频。事件携带 generation 和 utterance_id，旧音频与旧播放确认不再生效。
- AI 可邀请在场搭子接话，也可自然结束。用户有效参与后，连续 AI 发言计数重新开始，默认上限 30 次，由开发者配置；旧客户端保留原来的有界回应路径。
- 静音时发送等长静音 PCM，让识别器正常结束上一句话，不上传麦克风内容。支持免提切换、挂断、断线释放、通话时长与群内通话摘要。
- 首次麦克风授权期间不会把系统权限弹窗误认为用户离开通话；拒绝授权会显示错误提示。

通话过程中暂停该群文字回复与主动话题，避免通话、群消息自动朗读争用音频。当前版本在发起时选择成员，尚无通话中追加成员或后台持续通话。

预备下一位使用当前文字的临时上下文及预计计数，不修改真实通话历史、长期记忆或已完成发言数。
只有播放成功的真实回执才提交历史和计数；用户插话、换话题、暂停、挂断、回执超时或播放失败，都会丢弃旧预备任务及音频。
预备语音在消费前失败时，轮到该搭子后再尝试正常合成一次，不影响当前搭子播放。
后台通话统计中的 `prefetch_requests` 记录提前调度次数，`prefetched_audio_turns` 记录开始播放前首段音频已准备好的发言次数。

## 附件

群消息支持 `images` 或 `location`，分别复用单聊图片格式校验和位置模型。图片最大 5 MB，在服务器保存，通过归属校验后的群消息图片接口获取；消息列表不携带大段 Base64。位置显示为位置卡片，图片支持放大。附件纳入角色上下文，旧消息兼容空附件。

## 迁移与验证

SQLite 自动增加 `chat_group_messages.attachment_json`，并创建 `chat_group_calls`。通话记录单独保存参与角色、状态、时长与通话文字；删除群或清空记录同步清理。群消息序号通过数据库原子递增分配。

验证代码：`apps/server/tests/test_group_calls.py`、`test_group_call_discussion.py`、`test_group_call_prefetch.py`，以及客户端 `group_call_picker_test.dart` / `group_call_permission_test.dart`、输入栏与群聊回归测试。

开发阶段的调试截图与临时验证记录已清理；可通过上述测试重新验证。
