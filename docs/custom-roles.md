# 私人角色与手机录音复刻

## 使用流程

登录后进入「陪伴空间」，默认伙伴与自己的伙伴以横向白色卡片展示。
顶部为 Logo、标题与用户头像，不提供搜索、分类或排序按钮；底部固定「创建伙伴」。点击用户头像进入独立「我的」页面。
长按伙伴卡片可上下拖动排序，松手后写入手机 SQLite 的 `local_role_order` 表，按用户 ID 隔离，不调用后端排序接口。刷新、重新进入或重启 APP 都保留顺序；新伙伴追加到末尾，已删除伙伴不会展示。升级本地数据库保留聊天记录。
创建页分为伙伴昵称、伙伴设定、陪伴特征和伙伴声音四个区域，不再要求选择分类。每个伙伴选择 2～3 个特征，42 个可选特征对应统一的彩色矢量图标，不使用 Unicode 表情。
分类字段仅在后端保留，以兼容旧客户端与已有数据，新版安卓不提交该字段。「小孩」更名为「小朋友」，保留原 ID、头像、音色和会话，旧名称选择仍兼容。
卡片展示昵称、身份、简介、特征和真实未读数量，不展示最近消息或虚构在线状态。
点击卡片进入伙伴详情，查看身份、消息统计和最近四条真实历史消息，不使用虚构示例聊天。
只有「进入」按钮直接打开对应伙伴的持续对话，再次进入恢复该伙伴的记录。
点击「创建伙伴」填写昵称和设定；自建伙伴在详情页编辑或删除。创建和编辑页的保存按钮固定在底部。
「我的」集中管理用户资料、聊天性格和应用设置，不通过设置切换聊天伙伴。
未设置头像时使用 Bingo Logo；从相册选择图片后，可在圆形裁剪页面拖动和双指缩放。
声音可选择六个默认伙伴的系统音色、已有私人伙伴音色，或直接在手机上录制。
录音页面提供约 20～30 秒的中文朗读文案；少于 15 秒无法提交，最长录制 60 秒。
手机与后端均拒绝完全静音或没有有效幅度变化的录音，并提示检查麦克风。该检测不是语音识别，噪声、有效人声不足等仍由云端质量检查判断。
云端拒绝录音时显示对应的安全错误提示；日志仅记录操作、HTTP 状态及错误码，不记录密钥或临时录音下载地址。
合格录音可以回听，确认声音授权后提交复刻。复刻完成后可以生成中文试听，再保存角色。
复刻期间居中显示进度条及实际阶段（准备下载、云端复刻、验证音色），不伪造云端百分比。

每个自建角色仅对其创建者可见。删除角色会使其创建的复刻音色失效，使用该音色的其他角色切回女朋友的系统默认音色。
删除正在使用的角色时，当前助手也会切回默认角色。默认角色不可编辑或删除。

## 独立聊天空间

会话绑定用户 ID 和角色 ID，文字、图片、主动消息和通话记录归到对应角色。
切换角色不会清空旧对话，也不会把其他角色的内容放入模型上下文。
关系记忆与聊天推荐按角色会话隔离，基础用户资料记忆仍可共用。
角色卡片显示未读数量，进入与离开对应聊天时标记已读。
来电使用发起角色的名称、头像和声音，不受用户最近打开的其他角色影响。

SQLite 升级会按消息已有的角色 ID 或助手角色名称拆分旧混合会话，保留消息 ID、图片和通话关联。
无法识别角色的旧消息优先归到相邻回复的角色，否则归到用户原来的角色。
升级前建议备份数据库；安卓新会话缓存使用独立命名空间，不直接展示旧混合缓存。

## 部署

安卓端和服务端都需要更新，不能只更新 APK。
服务启动时兼容升级已有 SQLite 数据库，保留默认角色、历史消息和记忆。
自建角色使用独立 ID，名称不占用其他用户的命名空间。

默认使用 Yukisbox 将录音发布为临时 HTTPS 直链，供阿里云复刻服务读取。
第三方上传失败时，如果后端已有公网 HTTPS 地址，会回退到后端自己的临时录音下载地址。
公网服务器建议使用 `sample_host: public_url`，地址从 HTTPS 请求推导，无需额外配置 `public_base_url`。
本地后端不再需要公网地址，两份配置文件均使用以下默认值：

```yaml
voice_cloning:
  sample_host: yukisbox
  upload_endpoint: https://yukisbox.com/upload
  endpoint: ""
  timeout_seconds: 180
```

`endpoint` 留空时，沿用 `asr.realtime.url` 对应的百炼业务空间地址。
复刻和试听使用 `realtime_call.api_key` 与 `realtime_call.model`，密钥不会下发到安卓。
录音会上传到第三方服务，应在上线前向用户明确告知这一用途。
临时直链设置最多 10 次下载，任务结束后主动消耗剩余次数，并确认地址返回 404。
清理失败会记录警告；次数限制不是时间过期，进程异常退出可能留下尚未用尽次数的链接。
隐私要求较高时可切回 `sample_host: public_url`，并设置
`public_base_url: https://agentchat.cloud/bingo/api/v1`，使用自己的公网后端。
该模式的反向代理需要允许临时录音下载；两种模式均需允许至少 3 MB 的请求体。

后端的随机临时录音地址 10 分钟后失效，任务完成或失败后清除本地原始录音。
Yukisbox 副本的可访问性由上述下载次数和清理操作控制，不保证其内部物理删除。
任务保存在数据库，服务重启可恢复未完成任务；只有音色通过实时会话验证后才标记复刻成功。
网络失败后的重试会先查询同一任务的音色，避免重复创建。云端音色删除失败时会在后台重试。
试听不会写入聊天记录。
复刻成功后后台预生成原有长中文试听，不阻塞音色就绪；同一音色的并发试听合并生成。
成功试听在服务进程内缓存 10 分钟，最多 16 条、总计 32 MiB，重复试听无需再次等待云端合成。
每次试听仍检查角色归属、删除状态和当前音色；失败结果不缓存，重启后缓存清空。
第一次未预生成的试听仍需等待云端生成完整音频，不通过缩短试听文案或加快语速掩盖等待。

## API

以下路径均相对于现有 API 前缀：

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/roles` | 默认角色及当前用户的私人角色 |
| POST | `/roles/{id}/conversation` | 打开或恢复对应角色对话并标记已读 |
| POST | `/conversations/{id}/read` | 标记当前用户的会话已读 |
| POST | `/roles` | 创建角色，支持临时草稿 |
| PUT | `/roles/{id}` | 编辑自己的角色 |
| DELETE | `/roles/{id}` | 删除角色并使其拥有的音色失效 |
| POST | `/roles/{id}/voice-clone` | 提交手机录制的 16 kHz 单声道 PCM |
| GET | `/voice-jobs/{id}` | 查询复刻状态 |
| POST | `/roles/{id}/voice-preview` | 生成中文 WAV 试听 |
| GET | `/role-voice-samples/{token}` | 声音服务使用的短期录音下载地址 |

`/profile/options` 保留原有 `roles` 字符串列表，并增加 `role_details`。
`/me/profile` 的 `role` 字段同时接受角色 ID 和旧版内置角色名称，旧客户端无需更改已有调用方式。
私人角色需要使用 ID 选择；用户资料增加 `role_id` 和 `avatar_data`。
角色创建和修改接受 `categories`、`traits` 数组；各需 2～3 个有效且不重复的值。
旧客户端不传这两个字段时保留既有分类与特征。
会话列表增加 `role_id`；角色列表增加 `conversation_id`、`last_message` 和 `unread_count`。
推荐接口可传 `conversation_id` 查询或清除特定会话的推荐。

## 账号安全与生日

安卓主页顶部为 Logo、「陪伴空间」标题和用户头像。点击用户头像进入独立「我的」页面，个人资料、全局聊天性格与应用设置集中在此；角色页不再展示搜索框、分类筛选或独立详情图标。点击卡片进入角色详情，只有「进入」按钮直接打开聊天。性格通过 `PUT /me/personality` 单独更新，不改变角色身份、音色或用户资料。聊天顶部不再提供设置入口，空会话欢迎头像与所选角色一致。

默认角色的昵称与身份类型独立：甜甜（女朋友）、暖暖（男朋友）、小周（同事）、小田老师（老师）、星星（小朋友）、文清（家长）。角色 API 保留原 `name` 与 ID，新增 `nickname` 和 `role_type`，不迁移或清空已有会话、音色、头像。列表、详情和聊天标题展示昵称，身份类型单独展示；新版安卓不提供搜索。
未读角标位于「进入」按钮右上角，显示真实的角色会话未读数量；零条隐藏，超过 99 条显示 `99+`。进入对应角色聊天后标记已读。

首次登录仅填写用户头像、昵称、性别和生日，不再展示助手名称、角色或性格。头像默认使用 Bingo Logo，可从相册选择并进行圆形裁剪；生日采用年月日滚轮选择。昵称仍使用 API 的 `username` 字段，保持旧客户端及找回流程兼容。用户头像 `user_avatar_data` 与助手角色头像 `avatar_data` 独立。
资料与生日、恢复码摘要一次提交；恢复码仅展示一次。旧账号首次更新客户端时补填生日，已配置的找回生日不在此流程中覆盖。
生日是账号资料，不是秘密，也不会加入公开角色信息。找回密码同时要求手机号、用户名、生日和恢复码。
恢复码服务端只保存 SHA-256 摘要；重置成功后轮换恢复码并撤销全部登录会话，用户需保存新码并重新登录。
忘记密码接口对错误信息与不存在账号使用相同提示，每个手机号/IP 15 分钟最多 10 次请求。
当前限流为进程内实现，多 worker 部署还需在网关或 Redis 中统一限流。
修改密码入口位于设置页，需验证当前密码，修改成功后所有设备重新登录。
旧账号没有设置生日与恢复码时不能使用该找回方式；丢失恢复码也不能仅凭生日重置密码，需要其他经验证的恢复渠道。
注册时保存恢复码是本项目的离线恢复方案，参考 [OWASP 找回密码建议](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| PUT | `/me/user-profile` | 保存用户昵称、性别、生日和头像，完成首次登录资料引导；首次配置时领取恢复码 |
| POST | `/me/recovery-profile` | 登录后首次设置生日并领取一次性展示的恢复码 |
| POST | `/auth/reset-password` | 核验手机号、用户名、生日和恢复码后重置密码 |
| POST | `/me/password` | 使用当前密码修改密码并撤销会话 |
