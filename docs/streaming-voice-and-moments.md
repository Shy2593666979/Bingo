# 流式朗读与伙伴小互动（实验分支）

分支：`feat/streaming-voice-and-moments-20261007`。旧版已保留在
`ui/handwritten-font-c-20261004`，并快进合入本地 `main`。
本次功能经确认后通过 `main` 发布，实验分支保留用于追溯；部署仍需显式执行。

## 自动朗读

- 聊天页右上角的小扬声器开启/关闭；默认关闭，按登录账号保存在本地 SQLite。
  顶部不再并列显示电话按钮，通话入口仍保留在「＋ → 电话」中，伙伴名称保持居中。
- 开启后对新发起的回复生效，不朗读历史，也不重放当前已经开始的回复。
- `POST /chat/stream` 的可选字段 `read_aloud` 默认 false。
- 原有文字事件不变；开启时增加 `audio`（Base64、24 kHz 单声道 PCM16）、
  `audio_done`、`audio_error`。音频不落库，失败不影响文字。
- 模型原始增量与显示气泡分离：首个短句出来就送语音服务，不等整段回复；
  后面的模型生成、音频生成、客户端播放并行。长规划显示段落，但语音仍按短句生成。
- 使用对应伙伴当前音色，包括已有复刻音色；不由客户端指定任意音色。
- 手机采用独立媒体播放器，不开麦、不切换铃声模式；音量遵循媒体音量。
- 新输入、关闭开关、退出/后台、录音或电话会停止播放。
  `POST /chat/speech/{run_id}/stop` 只取消本人对应音频，不中断文字生成。
- 现有 Qwen 实时模型承担逐句朗读，不是逐 token 的双向 TTS 接口。
  聊天记录和气泡内容仍以文字模型输出为准。

## 四个菜单入口

- 一起专注：25/45/60 分钟，暂停/继续、结束；截止时间落库，完成或手动结束时仅发一条结束记录。
- 小约定：滚轮选择时间，保存后返回当前伙伴聊天；本地系统通知提醒。
  历史约定的编辑、完成、推迟 15 分钟和取消移至陪伴记录。
- 陪我入睡：睡前故事、轻声聊聊、安静陪伴；10/20/30 分钟定时，当前伙伴声音、暂停/继续/结束。
  每段目标约五分钟，初始约 1000～1200 中文字，按已生成音频的实测语速调整下一段字数。
  当前段播放期间最多预生成一个后续段，将本次故事前文作为临时连续性资料传入。
  最后一段按剩余时间缩短并自然收尾，不开启新情节。字数无法保证精确五分钟，定时为上限。
  客户端限制内存音频缓冲，向原生播放器只提前投喂约两秒，避免长故事撑满原生队列。
  语音失败会停止续播，不无限重试。进入后台暂停陪伴，本版不提供锁屏持续播放。
- 今日小记：心情、本机正文保存；保存结束后仅发送一条心情/记录状态总结，不上传正文。
  四种心情使用同一排矢量表情选择，新增与历史编辑页面共用，不使用系统 Emoji。
  历史列表、详情和编辑移至陪伴记录，功能页不堆放历史内容。

## 陪伴记录

- 「我的 → 陪伴记录」集中展示小记、约定、专注和入睡四类本机记录，按时间倒序排列，账号之间隔离。
- 功能页右上角「记录」只查看当前伙伴的记录；活动进行中不允许打开，避免历史管理覆盖运行中的状态。
- 约定分为进行中、已完成、已取消；编辑时间会更新本机通知，完成或取消会撤销通知。
- 历史内容的查看、编辑和状态管理只操作本机数据库，不调用模型、不新增聊天消息或上下文。
- 专注与入睡结束时留存简短状态记录；不保存故事正文和音频。已有小记及约定沿用原存储，无需迁移。

## 过程隔离与结束记录

- `POST /moments/stream` 是独立的模型与语音流，先验证本人对话和伙伴，使用伙伴设定、性格和音色。
  不读取普通聊天历史/长期记忆，不调用工具，不创建聊天消息、记忆、提醒或主动关心任务。
  故事正文和音频只在本次会话内存中保留，退出后释放，不写服务端或本地聊天记录。
- 四个入口仅在活动结束、创建约定保存或小记保存时通过 `POST /moments/finish` 写入一条简短总结，
  伙伴只回复一句。历史记录管理不触发新的模型回复。
- Moments 路由独立位于 `bingo/api/moments.py`，业务仍位于 `bingo/services/moments.py`。
  结束时先保存本机状态并返回聊天页，返回动画完成后才发起结束请求；聊天页先展示总结、再生成一句回应，
  不在功能页等待模型，不把导航生命周期绑在网络请求上。
- 结束请求使用账号、对话和活动会话 ID 派生的稳定消息 ID，重复请求不会新增结束记录。
  只有最终总结及这句回应会进入后续普通聊天上下文；原始故事/小记正文不进入上下文或记忆。
- 返回箭头和系统返回都会结束已开始的活动；进入后台只暂停睡前播放，不视作结束。

专注/约定/小记按账号和对话隔离存储在本机，不是云同步。
约定通知由 Android 本地 AlarmManager 触发，不依赖个推在线连接，通知尊重系统设置；
它是保存约定内容的本地提醒，不是假装 AI 在后台生成的新回复。
系统省电可能延迟非精确通知，强行停止应用仍可能阻断，不能承诺 OPPO 清后台后绝对可靠。
重启后恢复尚未到期的提醒；退出账号取消设备提醒，重新打开约定页面可恢复。
本版通知点击打开 Bingo，不直接跳转某个伙伴。
