# 系统架构

![Bingo 技术架构](media/bingo-architecture.webp)

## 客户端与接入

- Flutter Android 提供陪伴空间、角色独立聊天、伙伴编辑、个人资料及陪伴玩法。
- Android 负责录音、音频播放、实时通话、定位、通知和经用户确认的设备操作。
- 本地 SQLite 保存按用户隔离的会话副本；伙伴卡片顺序也在本地保存。
- 公网部署由 Nginx 提供 HTTPS，并将 `/bingo/api/v1` 转发至 FastAPI；开发环境可配置其他地址和 API 前缀。
- 普通 HTTP 接口使用 `EnvelopeRoute` 统一响应；WebSocket 保留事件协议，不套用 HTTP 响应封装。

## 服务端分层

| 模块 | 职责 |
| --- | --- |
| `api` | 路由、鉴权依赖、参数校验、HTTP 响应和 WebSocket 协议接入 |
| `services` | 用户、伙伴、会话、记忆、设备请求、地图、语音与陪伴玩法的业务流程 |
| `agent` | 模型调用、上下文组装、工具调用和聊天运行编排 |
| `tools` | 网络搜索、天气、来电邀请与设备闹钟请求 |
| `db` | SQLAlchemy 数据模型、数据库会话与持久化 |
| `background` | 延迟关心、推荐话题与次日早安调度 |
| `push` | 推送任务处理与个推供应商接入 |

系统提示词结合用户昵称、角色、性格、当前时间、可用地区信息和长期记忆。短期上下文中的用户消息附带时间标签，帮助模型区分过去的对话与当前发言。聊天会话按用户与伙伴隔离。

## 模型、语音与地图

- 文本与视觉模型通过可配置的模型客户端接入，不限定单一模型供应商。
- 语音服务包含录音识别、流式朗读、声音复刻、中文试听与实时通话；每位伙伴可以选择自己的音色。
- 实时通话通过已鉴权的 Bingo WebSocket 传输音频，服务端适配上游实时语音协议。
- 地图服务负责高德位置检索等能力；用户主动发送的地点与提示词使用的地区缓存分别处理。
- 个推由服务端发送消息，Android 负责通知权限、显示及点击跳转。送达仍受系统后台限制与厂商通道影响。

## 存储与后台陪伴

- **服务端 SQLite**：用户、伙伴、会话、消息、长期记忆、设备请求及调度状态等持久化数据。
- **Redis**：延迟任务、推荐话题缓存和有有效期的地区信息；不是长期记忆数据库。
- **后台调度**：每个发生对话的伙伴参与陪伴任务；默认 1 小时后关心、5 小时后预生成推荐，次日早上 7–9 点随机问候。任务依据新的对话更新或取消，不依赖用户打开页面才开始生成。
- **陪伴玩法**：一起专注、小约定、陪我入睡和今日小记由独立 `moments` API 接入；过程内容不作为普通聊天上下文，结束后返回聊天页面记录结果并触发回复。

## 安全边界

- 模型、语音与个推服务端秘密留在服务端；地图客户端 Key、推送 App ID 等公开客户端配置不属于这一秘密边界。
- 密码使用带盐 `scrypt` 哈希，移动端会话令牌通过 Android Keystore 加密保存。
- 模型可以提出设备操作请求，执行仍需用户在 Android 端确认。
- 生产部署使用 HTTPS；明文 HTTP 仅用于本地开发。
